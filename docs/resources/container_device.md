# truenas_container_device (Resource)

Attaches one device to a container: a bind-mounted host path, a GPU, a virtual
network interface, or a passed-through USB device.

~> **Requires TrueNAS 26.0 or newer.** The `container.device` API namespace does
not exist on 25.10 or earlier. Against an older server every operation fails
with a diagnostic naming the required version rather than an opaque
method-not-found.

Exactly one of `filesystem`, `gpu`, `nic` or `usb` must be set. A device is one
kind of thing; use a separate resource for each device you attach.

## Example Usage

```terraform
resource "truenas_container" "web" {
  name = "web"
  image = {
    name    = "alpine:3.21:amd64:default"
    version = "20260820_23:08"
  }
}

resource "truenas_container_device" "media" {
  container = truenas_container.web.id

  filesystem = {
    source = "/mnt/tank/media"
    target = "/srv/media"
  }
}

resource "truenas_container_device" "lan" {
  container = truenas_container.web.id

  nic = {
    type       = "VIRTIO"
    nic_attach = "truenasbr0"
  }
}
```

## Argument Reference

* `container` - (Required) ID of the container to attach to. Changing this
  forces a new device.

Exactly one of the following blocks. Changing which block is set, or any value
inside it, forces a new device: TrueNAS validates the attributes against the
device shape chosen at creation.

### `filesystem`

* `source` - (Required) Host path to bind-mount. Must be under `/mnt/`, so it
  lives on a pool rather than the boot device. May not contain braces.
* `target` - (Required) Path inside the container to mount it at. May not
  contain braces.

### `gpu`

* `gpu_type` - (Required) `AMD`, `INTEL` or `NVIDIA`.
* `pci_address` - (Required) PCI address of the GPU on the host, from
  `container.device.gpu_choices`.

### `nic`

* `type` - (Optional) `E1000` for broad guest compatibility, `VIRTIO` for
  throughput. Defaults to `E1000`.
* `nic_attach` - (Optional) Host bridge or MACVLAN parent to attach to, from
  `container.device.nic_attach_choices`. Empty leaves the interface unattached.
* `mac` - (Optional) MAC address. Generated by TrueNAS when unset, and the
  generated value is kept in state rather than being regenerated on each plan.
* `trust_guest_rx_filters` - (Optional) Trust the guest's receive filters.
  Faster, and only appropriate when the guest is trusted. Defaults to `false`.

### `usb`

* `vendor_id` - (Optional) USB vendor ID in hex, for example `0x1d6b`.
* `product_id` - (Optional) USB product ID in hex, for example `0x0002`.
* `device` - (Optional) Host USB device path, as an alternative to the
  vendor/product pair.

`vendor_id` and `product_id` identify one device together: set both or neither.
Set at least one of the pair or `device`, or the result is a USB controller with
nothing behind it. Available devices are listed by
`container.device.usb_choices`.

## Attribute Reference

* `id` - Numeric container device ID.

## Import

```shell
terraform import truenas_container_device.media 1
```

## Behavior notes

### One block per resource

Upstream models the device as a single `attributes` object discriminated on a
`dtype` field. This resource expresses that as four mutually exclusive blocks
rather than a free-form map, because the four shapes share no fields: a map
would accept any key and only fail server-side, and neither Terraform nor the
documentation could say what a valid device looks like.

Setting none of them, or more than one, fails at plan time.

### Detaching a device does not remove its storage

The API can remove the backing raw file or ZFS volume along with the device
attachment. The provider never asks it to: that storage has its own lifecycle
and is not something detaching a device was asked to touch. Remove it
deliberately if you want it gone.

A device that is in use is force-detached, so removing one from a running
container works rather than failing.

### An unrecognised device type is an error

If TrueNAS reports a device whose `dtype` this provider version does not model,
the read fails with a message saying so. The alternative would be state with all
four blocks empty, which Terraform would plan as needing recreation on every
run with nothing explaining why.
